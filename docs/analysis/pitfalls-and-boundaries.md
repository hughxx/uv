更新：2026-09-14。来源：[任务书](../任务书.md)、[接口文档](../接口文档.md)、官方样例与本地 demo 诊断。

2026-09-14 积分刷新：Q02 的公式主体已由新版任务书明确，原“分式无法识别”问题关闭；Q02 编号保留，仅跟踪取整、完成回合记账及零分母等执行边界。

## 1. 已知踩坑

| 编号 | 容易误做 | 正确处理及依据 |
| --- | --- | --- |
| P01 | 把角色每回合的 move 和 attack 当两个动作 | 每人最多一个动作；攻击同时占操作者与武器，任务书 §4.4、接口 §2.2 |
| P02 | 根据 response.txt 重复 ID 推断同人能连发动作 | 它是动作变体目录；还存在缺逗号的语法错误，不能直接作为 JSON 测试样例 |
| P03 | 每类武器各造 3 座 | 三种武器合计最多 3 座，任务书 L408 |
| P04 | 将建造覆盖当作升级／无损修复 | 覆盖后新武器 L1；旧武器资产会损失，任务书 L408 |
| P05 | 用曼哈顿距离或禁止斜穿角 | 八方向等步长、切比雪夫距离、允许斜穿夹角，任务书 L487、497 |
| P06 | 基地 pos 当左下角，或只占一格 | 是左上角，x 向右加、y 向下减；接口 §1.3.1 |
| P07 | 任务点和矿点当目的站位 | 它们属于阻挡物，应搜索合法相邻站位；任务点 2 的冲突文字见 Q07 |
| P08 | 丢弃 enemy 或机器人 targetTeam | 会漏掉可见障碍与防守归属；B01 已复现 |
| P09 | 夜晚第一轮再考虑工人返程 | 此时武器已经需要操作者；按实际路径倒排，含站位与冲突余量 |
| P10 | 多角色各自检查一次队伍余额 | 必须从同一预留账本扣减；25 金币双建 B02 已复现 |
| P11 | 所有角色背包视为公共背包 | 金币共享，物品并不共享；没有明确的角色间转移接口 |
| P12 | 用样例射程替正式数值，或完全忽略输入射程 | 样例与规则表冲突；保留版本，读取有效实时值并记录差异 |
| P13 | L3 电磁对路径上每个目标各伤 30 | 总能量 30，逐个按实际伤害扣减，任务书 L521 |
| P14 | 多发武器只传一个目标 | 加特林／火箭目标数等于等级；B04 已复现 |
| P15 | 本回合算出致死就删掉机器人，让人走进该格 | 伤害统一回合末结算；运动／反击的实际顺序待 Q04 验证 |
| P16 | 单价最高的矿必然值得挖 | 比较完整路线、采集、销售、返防时间和未来价格 |
| P17 | 任务失败可以原地无限重开同题 | 结束后消失、该点冷却 30 回合且任务数有限，任务书 L1123–1138 |
| P18 | 拉开拓者回家不会影响进行中任务 | 离开任务点周围一格即结束任务；中央调度需保护驻留约束 |
| P19 | HTTP handler 等 15 秒沙盒执行结束 | HTTP 收请求后 5 秒；15 秒限制针对判题器沙盒执行，结果下一回合返回 |
| P20 | `false` 动作结果等于一次队伍异常 | 规则明确区分字段／格式错误与碰撞等执行失败，任务书 §八“异常处理”末尾说明 |
| P21 | 宝藏没开成功就没消耗物品 | 只要召唤动作合法就消耗；结果 2/3/4 都可能耗掉用品 |
| P22 | 宝藏结果 2 永久排除位置 | 还可能只是没有到开启时间；不能丢掉时间维度 |
| P23 | 宝藏同轮竞争一定只有一个赢家 | 同回合双方都满足条件则都得奖励，任务书 L1190 |
| P24 | 商店英文名字自动纠错或全部转小写 | `AcientTablet` 就是材料中的拼写；Medicine 大小写冲突需 Q12 校准 |
| P25 | 按“一块矿”做工人排他锁 | 多人同采合法，尾矿甚至每人各得 1；应锁站位及动作而非一律锁整矿 |
| P26 | 冷却期间操作者永远不能干别的 | 角色没有绑定炮台；可以比较安全换炮／道具／驻留，但不能破坏下一次开火到位 |
| P27 | 构造了模拟器就等于掌握判题器 | 当前缺机器人 AI、弹道栅格和完整结算顺序；模拟结果需标记模型版本与不确定性 |
| P28 | 判题器没重拉进程，所以无需失败恢复 | 退出不重启正是需要内部故障隔离与降级的原因；不能靠重启恢复局内记忆 |
| P29 | 任务分只看基础奖励，或对部分通过也加速度奖 | 新公式完整完成为 `S+5*T/t`，部分为 `S*p`；只有完整完成有速度项 |
| P30 | 答案已经确定正确，仍固定等待几轮再提交 | 在无其他机会成本时，等待k轮损失 `5*T*k/(t*(t+k))` 的公式分值；取整可能掩盖小差额 |
| P31 | 用走到任务点的时间作速度分母，或自行把分母夹到1 | 分母是实际完成回合减接取回合；任务前路程仍有全局机会成本，t=0处理与完成记账时刻需Q02核实 |
| P32 | 用通用采矿／防守Task替代自进化任务会话 | 分开Job与ChallengeSession，后者需要驻留、工具往返、答案和计分状态；同伴评审§3.5 |
| P33 | 己方炮塔射程内都是安全区 | 只有符合昼夜、操作者、冷却及弹道条件才有实际火力；范围本身不是伤害保护 |
| P34 | 未来2–3轮路径预留永不失效 | 它是可撤销计划；实际移动失败、角色死亡、矿刷新及紧急换岗时重算 |
| P35 | 收益矩阵每行选最大就得到可执行团队方案 | 继续检查共享金币、炮台和通路；矿点可多人共享，不应一律容量1 |
| P36 | 把己方控制区奖励直接减成负路径边成本 | 首版移动／等待成本≥1，风险附加非负；防止绕圈领取奖励和破坏最短路假设 |
| P37 | 看到一个敌人离家就认定对方无法防守 | 检查其他操作者、可用道具及未知信息；区分事实、窗口推断与取胜证明 |
| P38 | 原始破绽消失就无条件取消整套打法 | 分开进入条件、持续安全条件和阶段转移；逼对手回防可能是预期成果 |
| P39 | 每轮小收益最大化可以自动连续运营 | 评价活跃Playbook剩余路线与收益转化，保留必要资源与切换成本；不能随意打断必要的准备动作 |
| P40 | 每次检测到同一机会就重新启动并花钱 | 给机会实例去重，按实际结果推进，过期／失败时进入明确分支 |
| P41 | 实时响应等于可随时修改正在执行的策略代码 | 当轮触发、赛间增补和局中热更新分开；版本切换不能破坏活跃方案阶段 |
| P42 | 已判断有胜势，就靠计划承诺／防抖坚持到脚本结束 | 新证据推翻必要前提时撤销相关判断并重评；允许另一独立打法接管，小幅估值波动与实质失效分别处理 |
| P43 | 每条事件回调各自发命令，或只有位置变化才检查策略 | 同轮事件基于完整快照集中协调；时间推进、预期落空与窗口到期也触发检查，避免动作覆盖和漏过期限 |
| P44 | 触发套路次数越多，已取得优势必然越大 | 分开预期、实际到账和相对领先；核对比较基线与收益期限，未兑现记录反例，不虚增胜势估计 |
| P45 | 每个打法单测不超时，就认为全部同时触发也能实时响应 | 所有候选共享整回合截止时间，预留响应预算；计算须有界／主动检查截止，普通异常捕获不是强制超时隔离 |
| P46 | 各打法自己的总分能直接比较，金币换升级后两份价值都保留 | 统一评估截止点、基线和量纲；区分实际Score与Utility，禁止窗口／期末、并行奖励和转化资产重复计数 |
