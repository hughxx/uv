## 4. 会显著改变设计的未决事项

1. 判题器真实结算顺序、弹道和机器人AI：决定防守布局、伤害预测及是否适合更深入搜索。
2. 任务计分取整与完成记账边界、题型、工具返回和环境：决定开拓者时间预算、SOP投入及任务与防守的收益权重。速度公式主体已明确，不再作为未决项。
3. 建造区域、任务点双格交互和回合起算：决定坐标／合法性内核。
4. 上下半场进程生命周期、请求重复与会话标识：决定状态隔离和缓存策略。
5. PvP具体规则和胜负未穷举分支：决定进攻型布局、远程压制及终盘决策。

对应问题、暂定处理和最小验证方式见 [Q清单](pitfalls-and-boundaries.md)。这些不阻塞当前文档交付，但会阻止把依赖它们的规则标为“已验证”。

## 5. 下一阶段的具体入口

先补齐／核对P0规则和一个真实任务闭环，再按 [architecture.md](architecture.md) 的P1–P3做最小自研闭环。开始实现时引用本文件已有授权与用户新要求，不重复询问已经明确的“是否自研”。本轮“先分析、不急着写代码”的边界不自动变成现在就实现全部模块的授权。

初版必须能给出可诊断的完整响应、记录工具任务状态、协调三个角色和共享金币。是否先投入某种高阶炮型、宝藏或进攻策略，留给可比较的真实对局结果，而不是本轮先拍板。
