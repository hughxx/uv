## 证据与维护约定

- **规则明确**：资料有直接表述，不代表已通过判题器验证。
- **本地复现**：在 demo 或构造样例上观察到结果，不能外推整场胜率。
- **静态确认**：源码直接支持的结论，实际触发范围另行说明。
- **推导／设计**：列出前提、比较对象和适用范围。
- **待验证**：资料缺失、存在冲突或尚无执行证据。

新增结论注明来源、前提、反例和验证状态。Bug 使用 B 编号，策略使用 G/H 编号，踩坑使用 P 编号，边界使用 E 编号，规则疑问使用 Q 编号；既有编号保持稳定。新证据优先更新对应主题文档，不另建重复的过程记录。

项目文档只保留技术事实、设计依据和验证结果，不收录聊天转述、个人信息、本机绝对路径或操作授权记录。个人工作笔记不纳入版本控制。
